# Registre des activités de traitement — modèle

> **Modèle à valider par un juriste** (nLPD art. 12 ; RGPD art. 30 pour les membres résidant en France). Rempli pour
> le pilote envisagé ; rien n'est en production. Les mesures citées sont celles du prototype, testées
> (`docs/audit/CLAIMS.md`).

| Rubrique | Contenu proposé |
|---|---|
| Responsable du traitement | Club des Affaires (coordonnées du secrétariat : à compléter) |
| Représentant dans l'UE | à vérifier (membres résidant en France) |
| Finalités | 1. adresser à un membre des demandes précises du Club ; 2. composer une capacité avec des membres qui y consentent ; 3. suivre les partenariats en agrégats (Suivi, bilan) ; 4. passe découverte d'un invité (90 jours) |
| Catégories de personnes | membres (représentants d'entreprises membres) ; invités du passe découverte |
| Catégories de données | identité (nom, entreprise, contact) — **séparée** du journal ; capacités déclarées ; réponses (oui / non / pas cette fois) ; consentements et reçus ; zone et langue déclarées |
| Données sensibles | aucune prévue |
| Destinataires | le secrétariat (agrégats, « < 3 » en entreprises) ; les autres membres seulement pour ce qui est consenti, par finalité |
| Transferts hors de Suisse | aucun prévu ; modèle d'IA Apertus servi par le CSCS (Lugano) — conditions à vérifier |
| Durées de conservation | consentement : jusqu'à son échéance ou son retrait ; passe découverte : 90 jours ; identité : jusqu'à la fin de l'adhésion ou « tout effacer » ; mode salle : effacé après la présentation |
| Mesures de sécurité | journal en ajout seul, identités à part ; purge réelle (« tout effacer ») ; jetons signés ; console protégée par jeton (aussi derrière un tunnel) ; seuil « < 3 » ; IA qui propose, membre qui décide ; photo de carte jamais conservée |
| Droits des personnes | accès (« Mes données »), retrait en un geste, effacement ; information FR / DE (`/confidentialite`) |
| Analyse d'impact | à faire avec un juriste au jalon « Lancer » |
